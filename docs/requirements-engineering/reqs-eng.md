<div class="joplin-table-wrapper"><table><thead><tr><th colspan="3"><p><strong>Onboarding and Profile Assessment Module (Mobile)</strong></p></th></tr><tr><th><p>No.</p></th><th><p>Components</p></th><th><p>Functional Requirements</p></th></tr><tr><th><p>OB-01</p></th><th><p>Guided Onboarding</p></th><th><ol><li>The system shall provide a guided onboarding flow that captures the user's financial situation before providing recommendations.</li><li>The system shall allow users to resume onboarding if they leave the app, preserving partially completed answers.</li></ol></th></tr><tr><th><p>OB-02</p></th><th><p>Eligibility Capture</p></th><th><ol><li>The system shall capture target population eligibility fields (age range, work/residence location) during onboarding.</li><li>The system shall execute server-side profile classification during onboarding.</li></ol></th></tr><tr><th><p>OB-03</p></th><th><p>Profile Assignment</p></th><th><ol><li>The system shall assign a behavioral profile based on captured financial data and display an explanation of the assignment.</li><li>The system shall allow users to review, accept, reject, or manually change their assigned profile.</li><li>The system shall allow users to request profile reassessment at a later time.</li><li>The system shall cache the current profile assignment and explanation locally for offline display.</li></ol></th></tr></thead></table></div>

<div class="joplin-table-wrapper"><table><thead><tr><th colspan="3"><p><strong>Taxonomy and Restriction Levels Module (Mobile)</strong></p></th></tr><tr><th><p>No.</p></th><th><p>Components</p></th><th><p>Functional Requirements</p></th></tr><tr><th><p>TX-01</p></th><th><p>Category Groups</p></th><th><ol><li>The system shall provide spending and income category groups that reflect Filipino financial realities.</li><li>The system shall deliver system taxonomy as pull-only catalog data from the server.</li></ol></th></tr><tr><th><p>TX-02</p></th><th><p>User Categories</p></th><th><ol><li>The system shall allow users to create custom categories and subcategories.</li><li>The system shall sync user-created categories and subcategories using user CRUD sync.</li></ol></th></tr><tr><th><p>TX-03</p></th><th><p>Restriction Levels</p></th><th><ol><li>The system shall allow users to mark expenses as protected or fixed so that the system does not recommend reducing non-negotiable spending.</li><li>The system shall validate restriction-level data against downstream budget and recommendation modules.</li><li>The system shall sync approved restriction-level data using user CRUD sync.</li></ol></th></tr></thead></table></div>

<div class="joplin-table-wrapper"><table><thead><tr><th colspan="3"><p><strong>Financial Accounts, Income Sources, and Obligations Module (Mobile)</strong></p></th></tr><tr><th><p>No.</p></th><th><p>Components</p></th><th><p>Functional Requirements</p></th></tr><tr><th><p>FA-01</p></th><th><p>Financial Accounts</p></th><th><ol><li>The system shall allow users to create, view, edit, and delete financial accounts offline.</li><li>The system shall display the current balance for each financial account from local data.</li><li>The system shall scope all financial account data to the authenticated user.</li><li>The system shall sync financial account records using user CRUD sync.</li></ol></th></tr><tr><th><p>FA-02</p></th><th><p>Income Sources</p></th><th><ol><li>The system shall allow users to record income sources with amount, frequency, and associated account details.</li><li>The system shall sync income source records using user CRUD sync.</li></ol></th></tr><tr><th><p>FA-03</p></th><th><p>Obligations</p></th><th><ol><li>The system shall allow users to record obligations with amount, due date, frequency, and category.</li><li>The system shall sync obligation records using user CRUD sync.</li></ol></th></tr><tr><th><p>FA-04</p></th><th><p>Ownership and Sync</p></th><th><ol><li>The system shall validate foreign key references against the current user's ownership boundary before local persistence and before remote sync application.</li><li>The system shall use tombstone deletes for synced entities.</li></ol></th></tr></thead></table></div>

<div class="joplin-table-wrapper"><table><thead><tr><th colspan="3"><p><strong>Ledger, Transactions, Templates, and Recurring Records Module (Mobile)</strong></p></th></tr><tr><th><p>No.</p></th><th><p>Components</p></th><th><p>Functional Requirements</p></th></tr><tr><th><p>LG-01</p></th><th><p>Transaction Entry</p></th><th><ol><li>The system shall allow users to record income, expense, and transfer transactions with amount, date, category, account, and notes.</li><li>The system shall allow users to record transactions offline, with changes written to local SQLite immediately.</li></ol></th></tr><tr><th><p>LG-02</p></th><th><p>Templates</p></th><th><ol><li>The system shall allow users to create transaction templates from existing or new transactions.</li><li>The system shall allow users to apply a template to record a new transaction quickly.</li></ol></th></tr><tr><th><p>LG-03</p></th><th><p>Recurring Records</p></th><th><ol><li>The system shall allow users to set up recurring income or expense records with defined frequency and end conditions.</li><li>The system shall generate and queue recurring transaction entries automatically.</li></ol></th></tr><tr><th><p>LG-04</p></th><th><p>Transaction Management</p></th><th><ol><li>The system shall allow users to edit, delete, search, sort, and filter transactions.</li><li>The system shall display local balance effects immediately after transaction creation or modification.</li><li>The system shall sync transaction records using user CRUD sync.</li></ol></th></tr></thead></table></div>

<div class="joplin-table-wrapper"><table><thead><tr><th colspan="3"><p><strong>Dashboard Module (Mobile)</strong></p></th></tr><tr><th><p>No.</p></th><th><p>Components</p></th><th><p>Functional Requirements</p></th></tr><tr><th><p>DA-01</p></th><th><p>Financial Overview</p></th><th><ol><li>The system shall display current balance, recent activity, budget status, alerts, savings goals, debts, and forecasts on the dashboard.</li><li>The system shall render the dashboard from local SQLite data, not server-only endpoints.</li><li>The system shall update the dashboard immediately after local ledger writes.</li></ol></th></tr><tr><th><p>DA-02</p></th><th><p>Dashboard Degradation</p></th><th><ol><li>The system shall display stale or cached labels when downstream module data is unavailable.</li><li>The system shall degrade gracefully for missing downstream modules without blocking dashboard display.</li></ol></th></tr></thead></table></div>
